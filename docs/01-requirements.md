# 01 · 需求分析与范围

## 1. 产品目标

为高校一年级《设计色彩》课程建立“一名学生、一颗星球”的原创作品空间：学生在 Studio 制作星球，教师汇集班级宇宙，访客浏览艺术展览；后续把每次作业转为可追溯的档案，再由学生选择是否接纳 AI 提出的成长元素。原创绘画优先，程序效果辅助。

来源为用户提供的《COLORVERSE 色彩宇宙：Codex 项目启动与第一阶段开发指令》。当前用户要求只完成 docs/ 设计，优先于附件的开发指令。以下 P1 指未来第一阶段交付，并非本轮实现范围。

## 2. 使用者与主要路径

| 使用者 | 主要路径 | 权限边界 |
| --- | --- | --- |
| 学生 | 创建星球→导入原创→调色与场景→保存→导出；未来提交作业、选择生长 | 仅拥有自己课程中的内容；作者署名不作为身份凭证 |
| 教师 | 导入包→检查→编排宇宙→展示；未来布置和批改 | P1 为本机演示操作；P2 才按班级成员关系授权 |
| 访客 | 搜索筛选→选择星球→进入场景→查看公开作品 | 只读公开快照，不接触作业草稿、分数或评语 |

P1 的本地修改不会自动同步其他电脑。可把教师汇总后的展示快照作为静态站点发布，浏览者不会修改教师的本地宇宙。共享编辑、实时协作均不在前三阶段承诺内。

## 4. 暂定业务口径

1. “一人一球”限定为每个班级课程实例一颗星球，同一学生跨学期可有不同星球。跨学期延续通过复制/继承内容完成，不把旧课程权限带入新课程。
2. 默认学生内容私密。班级分享和公开展览都是显式发布，不随“提交作业”自动公开。
3. P1 文本均按纯文本处理，不支持任意 HTML、脚本或插件。作品包不含可执行代码。
4. 首要设备是 8 GB 内存、集成显卡、1080p 的 Windows 10/11 电脑。验收浏览器为测试时的 Chrome/Edge 稳定版本；其他浏览器尽力兼容。
5. 原创图片为 sRGB 展示目标；保存原始字节及色彩信息，派生展示图可能发生色域转换，不承诺专业印刷色彩管理。
6. 音频第一阶段允许作为已声明素材随包保存与还原；播放、混音和录音不作为 P1 核心验收。渲染器未支持的可选能力需明确提示，不能静默丢数据。

## 5. 需在开发门槛前确认

| 问题 | 暂用假设 | 最晚确认点 |
| --- | --- | --- |
| 三年是否每年一学期或两学期？40 人是否每年换新班？ | 基线每年一学期、每年 40 名新生；另算两学期 | 云端容量采购前 |
| 最大单幅原图、每份过程图数量、是否需专业色彩管理？ | 20 MiB/幅、每作业 3 幅，原始文件保留 | P0 素材实测 |
| 公开署名、允许公开哪些作品、保存多久？ | 昵称、教师审核发布、教学资料三年容量预算；保留期限另定 | P2 权限设计冻结 |
| 校内统一登录、服务器区域、学校域名与发布政策？ | 先本地演示；P2 OIDC 身份接入作为优选 | P2 开工 |
| 预设球体是否要求真实三维自转？ | 2D 明暗球 + 纹理偏移满足基础效果 | P1b 前 |

## 6. 主要调整建议

不要把“全班 300 颗”理解为同时渲染 300 个完整内部场景；远处只看缩略图。不要把“完整 ZIP”解释为仅导出 JSON；必须封装引用闭包。不要把 AI 情绪判断作为心理结论或评分依据，只作为学生可拒绝的视觉建议。不要把本地自动保存等同于备份；浏览器数据可被清理，必须提供导出和恢复。


## 2026-10-10 用途与优先级调整

用户确认色彩作业较多，本项目主要由学生主动选择想展示的作业上传；完整作业管理暂缓。保留22已实现的本机模块，下一开发重点转向自选作品档案与星球成长交互。预制元素/实时生图/可选模型分析的比较与建议见[23](23-showcase-upload-and-growth-direction.md)。本文记录用途调整，23的交互和素材扩展尚未实现，不改变既有测试数量。
