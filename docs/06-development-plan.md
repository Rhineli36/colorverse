# 06 · 分阶段开发计划

## 1. 当前范围与估时口径

当前只完成设计基线，不生成前后端脚手架。后续按一个熟悉 TypeScript 的全栈开发者、教师每周能反馈、演示素材有明确授权估计净工程人日；不含素材绘制、等待审批、采购、正式运营。排期需在 P0 后重新估算，另留约 25% 缓冲。

P1a 是最小闭环；P1a 完成不等于附件全部第一阶段要求完成。P1b 补齐十类效果、跨机恢复、教师备份和性能验收后，才能宣布 P1 完整交付。可选预设球体的实现程度要明确列入报告。

## 2. 有序实施清单

- [ ] P0：冻结协议字段、收集真实学生素材、验证渲染和 ZIP 额度，建立契约/迁移 fixture。
- [ ] P1a-1：搭建前端和统一渲染器，完成 5–8 颗演示星球、镜头/搜索/进入返回。
- [ ] P1a-2：接通原创图片、非破坏调色、两种基础光效和编辑命令历史。
- [ ] P1a-3：实现内景图层、文本/图片/档案热点和示例作品。
- [ ] P1a-4：实现 IndexedDB 自动保存、JSON/ZIP 校验与跨机恢复、教师导入宇宙。
- [ ] P1a-5：完成模拟成长接受/拒绝/撤销/刷新恢复及防重复测试。
- [ ] P1b 增量：学生本人/教师全班的星球移动模式与受控轨迹预设；协议迁移、保存冲突和越权验收，见14号文档。
- [ ] P1b：补齐效果目录、宇宙备份、可访问性、异常处理和 300 颗预算验证。
- [ ] P2：增加身份和课程作业事务、私有媒体、发布快照和学期归档。
- [ ] P3：增加可替换模型 Worker、审核和预算限制，先小班试点再逐步开放。

## 3. P0 · 设计验证与脚手架（3–5 人日）

输入：本目录；至少 10 幅真实 PNG/JPG/WebP（透明边缘、大尺寸、不同色彩配置）、一段音频、目标机房设备信息。

任务：锁定运行时/依赖版本；建立 workspaces、TS/lint/format/CI；从协议生成类型/校验器；实现 2–3 个小型原型验证 Pixi 滤镜、透明边缘、2048 纹理与限额 ZIP 解包。正式功能尚不扩展到课程后端。

退出门槛：目标电脑能加载带透明边缘的原创图并调整滤镜；内存和 ZIP 限额有实测；引用缺失和不支持版本可定位；确认可选球体是 2D 还是 3D。若 WebGL 或素材体积不满足预算，先调整画质/包上限，再推进 UI。

## 4. P1a · 最小可运行闭环（15–22 人日）

| 子阶段 | 依赖 | 交付与验收 | 估时 |
| --- | --- | --- | --- |
| 1 宇宙与统一渲染 | P0 | 5–8 颗有区分度的演示；拖动缩放/悬停/搜索/筛选/进出；返回状态恢复 | 3–4 天 |
| 2 Studio 与原创素材 | 1 | PNG/JPEG/WebP、变换、六项调色、背景、柔光与呼吸；原图 hash 不变；撤销重做和重置 | 4–6 天 |
| 3 内部艺术空间 | 2 | 前中后景、渐变、视差、漂浮、30 个以内热点、静态作品档案卡 | 3–4 天 |
| 4 保存和教师汇集 | 2、3 | IndexedDB 配额/冲突、JSON/ZIP、校验报告、教师导入/显示/隐藏/删除；两机往返内容一致 | 3–5 天 |
| 5 模拟成长 | 3、4 | 固定 mock 提案、预览、接受/拒绝/撤销、持久记录；重复执行保护 | 2–3 天 |

每个子阶段完成后运行与该变更相关的领域和浏览器测试，失败先修复再依赖它开发。不要一次填满未来页面。P1a demo 不调用任何真实模型 API。

## 5. P1b · 第一阶段完整交付（7–12 人日）

补齐十类效果和星环；统一密度/强度/速度控件；预设球体作为可选范围 1–3 人日，若需真正 3D 另行评估；音频资源随包保留。完成宇宙完整备份/超限分批集合、恢复报告、帮助文案、键盘导航、减少动态效果和 GPU 失败只读降级。

交付 5–8 个不同艺术方向的演示（如水彩云雾、暖色拼贴、冷色晶体、墨色静谧、荧光夜景、雪境），原创图为主，提供作者/许可说明，不只换同一球体颜色。300 颗性能 fixture 可以复制测试数据，不能冒充 300 个学生原创作品。

执行 08 全部 P1 测试与目标机房复测；README 必须写安装/运行/构建命令、支持浏览器、数据保存位置、ZIP 恢复和限制。发布最小静态预览、演示素材清单、测试报告和已知问题；所有私人真实学生资料用合成数据替代。

P1 总计约 25–39 人日（含 P0，不含可选球体新增范围），加 25% 缓冲约 31–49 人日，单人约 6–10 工作周。若缩减到课堂演示，只能标注 P1a，不宣称完整第一阶段已交付。

### 已确认的后续运动控制增量

新增学生可选静止/慢速/快速、圆形/椭圆/八字/往返轨迹预设；活动范围有界，不开放手绘路径。学生只可控制归属星球，教师可控制当前班级全部星球；模式与锚点按单条目原子保存。详细数据归属、兼容迁移、并发与测试顺序见 [14-planet-motion-controls-plan.md](14-planet-motion-controls-plan.md)。状态为待实现，尚未计入原7–12人日预算；实施前补充估时。

## 6. P2 · 在线课程作业（20–32 人日）

依赖：稳定 P1 协议、P2 权限开放问题得到确认、可用登录源/服务器/私有存储。

实施顺序：身份与班级成员→关系迁移与服务器授权→私有素材直传及校验→作业与不可变提交→教师批改/退回→自动档案→发布快照→学期归档与恢复。先做一个班级的纵向闭环，再做批量管理。

门槛：跨用户/跨班级越权测试全部通过；重复提交只生成一个版本；截止时区和迟交测试正确；真实档案替换示例无需重写 renderer；教师评语不会出现在公开响应、ZIP 或媒体链接中；测试环境完成数据库与对象联合恢复。

P1 本地作品迁移采取用户主动导入、服务端重新认领归属、hash 校验；提供导入前备份。分班灰度开放，保留本地导出路径；遇到严重问题暂停写入而不强行降级数据库 schema。

## 7. P3 · AI 生长（10–18 人日）

依赖：可靠的 P2 提交版本、私有资源授权、预算与教学审核规则。先对 20–30 份获授权样本进行离线人工评估，再接真实 Worker；没有学生授权的真实作业不外发。

实施顺序：MockProvider 契约与测试→真实 adapter 能力验证→任务租约/次数/费用限制→受限提案验证→教师审核/学生确认→生长历史和补偿→质量监控。模拟演示始终可用。

门槛：模型违规 JSON/未知预设不能进入场景；超时/429/重复回调不重复生长；停用模型供应商不影响现有作品；密钥不出现在前端包与日志；累计费用可核对并有熔断。评估可解释性和学生接受度，不以模型自评分作为质量证据。

## 8. 每阶段交付报告

固定报告已实现与未实现需求 ID、测试环境/命令/结果、性能样本、已知问题、迁移兼容范围、下一阶段阻塞项。版本说明明确 doc schema / package schema / preset versions。全阶段发布均可撤回静态前端，但涉及数据格式的回滚必须依靠兼容读取或备份恢复，不能假设旧代码可直接读取新数据。
