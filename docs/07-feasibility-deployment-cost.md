# 07 · 可行性、部署与成本

估算日期：2026-10-09。以下容量是可复算规划假设，费用是人民币预算区间，不是厂商报价或承诺。实际采购须按地域、计费方式、访问量及模型核价；不把促销首年价格用于三年预算。

## 1. 三阶段评估

| 维度 | P1 编辑展示 | P2 课程作业 | P3 模型与生长 |
| --- | --- | --- | --- |
| 可行性/难度 | 可行，中等；难点是媒体还原、统一滤镜、低配置性能 | 可行，中高；难点是授权、提交历史、发布隔离与备份 | 参数驱动可行，中高；质量和供应商稳定性须实测 |
| 基础设施 | 本机浏览器与静态资源服务，可不付云费用 | API、PostgreSQL、私有对象存储、HTTPS、备份 | P2 + 持久任务 Worker、预算计量和服务端密钥 |
| 存储/带宽影响 | 本地图片多于 JSON；静态发布按展示图消耗流量 | 原图和提交版本占主要容量；直接上传，按需授权读取 | 保存参数/事件很小；模型图片上传和调用计费单独统计 |
| 现成开源库候选 | React、Vite、PixiJS、Zustand、Zod、idb、JSZip、Vitest、Playwright | Fastify、PostgreSQL、OIDC 客户端、供应商 SDK；按需要选 SQL 工具 | JSON Schema 校验与现有 Worker；模型 HTTP/SDK adapter |
| 架构调整 | 建立协议和边界是重点 | 新增后端与权限，但不重写 renderer/Studio | 新增任务与模型适配，不替换现有图层模型 |
| 更简单稳定的方案 | 原创图片+2D 层+有限效果；默认不用 3D | 单应用+单关系库；校内统一登录；不做协同编辑 | 固定规则或教师挑选预设始终可用；无需逐次生图 |

暂不承诺模型识别能准确描述所有艺术风格；技术 feasibility 不等于教学效果验证。学生可以完全手动创作，AI 服务不可用时已保存内容照常展示。

## 2. 推荐部署及迁移

P1：Vite 构建后的静态文件通过本机开发服务器、学校静态服务器或普通静态托管访问。无需账号数据库或真实 AI Key；默认本地演示数据不得包含真实隐私。暂不承诺首次加载后彻底离线运行，若课堂无网需要单独安排本地资源及 PWA 验证。

P2：静态前端/CDN + 一台 2–4 vCPU、4–8 GB API 主机作为起始配置 + PostgreSQL（起始 20 GB，实际压测后定）+ 私有对象存储。此规格是规划起点，不能替代 40 人并发提交和教师批量浏览压测。测试和生产配置/桶/数据库分离，数据库不暴露给浏览器。

P3：同一代码库单独 Worker 进程，最初可同主机但限制并发（暂定 2）；任务变重再独立扩容。API Key 和存储密钥在服务端环境或密钥管理器，前端只获得最小授权上传/读取凭证。

迁移能力：应用以容器或普通 Node 服务部署，配置通过环境变量；ObjectStore 包装 put/get/head/delete/signUrl；不要假设不同“S3 兼容”服务的权限、分段上传和签名完全一致。跨供应商迁移流程为复制私有对象→校验 hash/数量→迁移 DB→配置切换→抽样恢复→保留旧存储宽限期；媒体 URL 不写进 PlanetDocument，因此无须重写作品。

学校网络出口、域名发布条件、账号供应商和允许的模型服务区域由学校在上线前确认；本报告不对具体合规要求作法律判断。

## 3. 三年存储模型

使用十进制单位：1 GB=1000 MB；协议限制使用 MiB，勿混算。基础情境为每年一个课程学期、每年 40 名学生、每学期 12 次作业、连续三年；三年共 120 颗课程星球。若同一批 40 人长期沿用星球，仅星球基础素材部分减少，作业量不变。

### 每份作业的平均新增媒体

| 项目 | 假设 | 每份作业 |
| --- | --- | ---: |
| 原图 | 1 张成品+2 张过程图，每张 10 MB | 30 MB |
| 展示图 | 3 张，每张 1.2 MB | 3.60 MB |
| 缩略图 | 3 张，每张 0.08 MB | 0.24 MB |
| 可选音频 | 25% 的作业含 4 MB 音频 | 1.00 MB |
| 首次提交合计 | 上述相加 | 34.84 MB |
| 修改后新增媒体 | 平均 1.5 个版本，新增版本有 50% 字节改变；系数 1+(1.5−1)×0.5 | ×1.25 |
| 含版本平均值 | 34.84×1.25 | **43.55 MB** |

未改变文件按内容 hash 复用；这是假设的媒体复用比例，不是说“有版本管理就自动节省一半”。JSON、评语和事件通常很小，计入余量。历史版本不重复存相同图片字节。

### 容量结果

| 情境 | 作业数 | 作业媒体 | 星球额外素材 | 加 20% 余量 | 建议在线 / 含一份完整备份容量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 一年一学期，三年 | 40×12×3=1440 | 62.712 GB | 120×25 MB=3 GB | **78.8544 GB** | **100 GB / 200 GB** |
| 一年两学期，三年 | 40×12×6=2880 | 125.424 GB | 240×25 MB=6 GB | **157.7088 GB** | **200 GB / 400 GB** |
| 无媒体复用，一年一学期 | 1440，版本系数改为 1.5 | 75.2544 GB | 3 GB | 93.90528 GB | 至少 100 GB / 200 GB，监控提前扩容 |
| 高素材量，一年一学期 | 每图20 MB、两个版本全部变更 | 186.7392 GB | 3 GB | 227.68704 GB | 250 GB / 500 GB |

高素材量公式：[(3×20)+(3×1.2)+(3×0.08)+1]×2×1440/1000=186.7392 GB。20 MB 仍在暂定 20 MiB/图上限内。实际音频、RAW/视频、更多过程图或更多班级会改变规模，当前协议不支持 RAW/视频。

20% 余量包含展览专用派生副本、少量 JSON/事件/临时导出与波动；若长期保留许多独立展览快照或导出包，需单独增加，不应无限依赖余量。原始对象存储版本历史也可能计费，建议不变文件键+有期限的备份策略，避免无界版本链。

PostgreSQL 不存媒体：该班级规模的结构化数据粗估 0.5–2 GB 以内起步（取决于文档 revision 和日志），采购 20 GB 级别用于索引/余量；WAL、备份和日志按独立策略计量。这是初步估算，P2 用真实场景文档测量。

## 4. 网络流量模型

常规课程一个活跃月示例：40 学生×20 次访问×10 MB=8 GB；教师 480 份作业×3.84 MB 展示媒体≈1.84 GB；500 次展览访问×12 MB≈6 GB；合计约 15.84 GB，加导出/缓存冷启动可预算 20–50 GB/月。首次加载只是外观缩略图，访问深度决定实际用量。

三年末下载一次完整作品档案可能产生约 79 GB 流量，因此日常预算可按 100 GB/月留余地。1 万次公开访问×12 MB=120 GB，10 万次=1200 GB；公网流量可能比存储更贵。CDN 缓存节约回源但不消除边缘下行费用，不要重复或遗漏计算。

上行是否计费、CDN 回源、跨地域复制、请求次数、归档恢复和图像处理均需核对供应商账单；容量单价不能代表总成本。[腾讯云 COS 价格入口](https://buy.cloud.tencent.com/price/cos)、[请求费用说明](https://cloud.tencent.com/document/product/436/53861)

## 5. 分类月度预算（P2，基线保守容量）

下表是供立项讨论的预算单价，未宣称来自某个实时价目表。官方采购入口用于后续逐项替换假设；含税、资源包折扣和地区差异未纳入。

| 费用 | 用量/假设单价 | 月预算（元） |
| --- | --- | ---: |
| API 服务器 | 一台小型常驻实例 | 80–250 |
| 数据库 | 小型 PostgreSQL 独立/托管实例 | 100–300 |
| 对象存储 | 在线+一份完整备份共200 GB，假设0.10–0.20元/GB/月 | 20–40 |
| 网络下行 | 100 GB，假设0.30–0.80元/GB | 30–80 |
| 请求/少量派生处理 | 预算项，随读写/缩略图变化 | 5–20 |
| 日志、数据库备份及监控 | 独立预算，不重复计媒体备份容量 | 20–80 |
| 合计（不含 AI） | 255–770元/月 | **255–770** |

按全部 36 个月都预留三年末容量，三年保守预算 **9180–27720 元**。按实际容量逐月增长可更低。按 400 GB 双学期容量，存储项约40–80元/月，其他条件不变总计275–810元/月。流量增长要另加。域名、人工开发、日常运维人力、复杂监控、高可用冗余、跨地域灾备、税费和大型公开展览不在上述预算内。

更低成本：校内已有静态服务或教学服务器可减少现金采购；数据库与 API 同机减少租金但增加单机故障影响。推荐先验证小班，再按学校可靠性要求采购，不用复杂云架构解决 40 人规模问题。

## 6. AI API 与 Worker 费用

P1 为 0：只运行 MockProvider。P3 默认每份作业一个自动提案，1440 次基础调用；用 20% 的修复/重试预算估算 **1728 次/三年**。每份最多两个版本触发时变为 **3456 次**；硬限制在 05 中定义，人工重试也计入。

通用费用公式：`输入token/1e6×输入单价 + 输出token/1e6×输出单价 + 独立图像费用（如供应商采用此计价）`。如果图像已经折算成输入 token，不再加收一遍图像费用。应记录模型、地区、请求 ID 和实际 usage，使用压缩展示图减少无效输入。

采购前规划单次 **0.02–0.20 元**的假设区间（非真实模型报价）：1728次≈**34.56–345.60元/三年**；3456次≈69.12–691.20元/三年。高价模型/高分辨率图片可能显著超出；例如单次1元时1728次即1728元。API 工作量分布在教学周，不能据三年月平均掩盖短期峰值。

Worker 初期复用服务器时可能无新增实例费，独立部署另预留50–150元/月。按实际需要的月份计费，全年常驻36个月即额外1800–5400元。设置月预算例如50元、班级日次数、调用前预留和达到上限停机，额度由教师/管理员配置。

不提供未验证的“某模型最低价格”结论。正式接入前以相同的授权样本比较结构化成功率、生成时间、作品适配度和真实费用；支持多模态与 Schema 的细节按供应商/模型复核，见 05 的官方参考。

## 7. 运维和恢复目标

P2 先采用每日数据库备份、不可变对象清单及独立备份，目标 RPO≤24小时、RTO≤1工作日；这些是待演练的目标，不是已实现 SLA。若要求更小 RPO，应增加持续 WAL 归档与对象同步并重新预算。每学期至少一次从空环境恢复抽样作品、原图、提交、评语、发布和成长事件。

监控保存失败、空间余量、上传失败、导入错误、API延迟、任务积压与费用阈值。日志用资源 ID 和错误码，不写学生完整作品、私密评语或密钥。容量/流量达到预算70%提醒、90%限制非必要批量导出；备份恢复失败优先于新增功能处理。
