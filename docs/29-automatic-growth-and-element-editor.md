# 29 · 自动生长与元素专用编辑器

日期：2026-10-11。按[28](28-element-focused-editor-plan.md)实施，延续既有 Repository、成长事件、revision 和原始素材协议。

## 学生操作

1. 「编辑你的星球 → 添加展示作品」提交图片、标题及说明。提交入口说明会自动产生一个小元素。
2. 作品先独立保存，再由本地确定性规则生成并接受一个默认小元素。进入星球欣赏模式，播放约0.85秒的淡入舒展，不强制进入编辑器。
3. 点击画面里的元素或「编辑元素」按钮，进入元素专用编辑器。展示作品列表也提供「编辑生长元素」。
4. 上方选择8种现有造型，中间直接拖动及角点缩放，右侧修改颜色、饱和度、大小、光晕、透明度、自身动态和粒子。没有横纵位置滑条，也没有环境上传、背景或其他图层设置。
5. 底部撤销一步、重做、重置当前元素、确定并返回。取消丢弃这次调整，保留已提交作品和默认元素。重置恢复进入编辑时的元素，不恢复整个星球。

方向键微调，Shift加快；拖一次对应一步历史。静止/漂浮/旋转/呼吸作用于元素自身；星尘/萤火粒子独立可选。整颗星球在宇宙中的运动仍由原「运动」页控制，已补充明确说明。欣赏模式保持只读访客查看作品来源，学生本人或教师才进入可写编辑。

## 保存、失败与兼容

- `ShowcaseService.grow`复用现有提案/接受事务。同一展示档案只有一个成长事件；默认大小0.45，位置在内景的受限可见范围。默认图层和接受记录在同一个事务保存。作品和成长分开提交，成长失败或达到既有24次/50图层上限时保留作品；列表可重试，已接受/拒绝/撤销事件不重新抽取。
- 新规则登记为`showcase-auto-v3`，不回写旧记录。此前保存的v2待确认建议仍可恢复预览并完成接受；演示提交也保留原验收路径。
- `GrowthElementService`先检查归属，`LocalWorkspace.updateElement`在ownership/planets/revisions事务中再次授权并检查revision。只更新一个已接受的预设图层；身份、种子、所属场景、层级、锚点不能改变。学生只能保存自己的元素，教师沿用本地演示授权范围。
- 元素编辑采用独立内存会话，只有确定时保存新PlanetRevision。全局自动保存不会写入局部草稿。并发冲突/保存失败保留调整，不覆盖另一窗口；主导航提示先确定或取消。取消不撤销作品提交。
- 当前图层保存最新外观，成长事件保留生成时的参数与准确作品来源。成长补偿按layerId移除编辑后的同一层，保留作品和历史，不要求最新外观等于出生外观。
- 新可选`particleStyle=stardust|fireflies`使用`growth-particles@1`能力，省略时兼容旧文档，不向旧作品填充默认字段。声明该能力的作品需新版读取；结构Schema同步生成，原图/hash不变。Planet版本仍1.0.0，Universe运动版本仍1.1.0。

## 渲染与预算

新生动效使用既有渲染时钟，不保存逐帧变化；仅本次生成播放，离开后不重播。减少动态效果时直接显示静态元素。元素粒子跟随同一容器，常规每层12点，低质量6点；先从场景共享1000/300粒子预算中预留，再分配装饰粒子。没有新ticker、纹理素材或模型请求。

编辑时只当前元素有拖动覆盖层；其他场景图层提供上下文。参数预览复用统一渲染器和原始素材缓存。8种仍为程序图形原型，不宣称30种正式美术或机房GPU性能已验收。
