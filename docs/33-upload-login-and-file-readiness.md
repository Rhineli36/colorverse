# 33 · 上传、文件管理与登录的上线核对

日期：2026-10-11。用户要求先部署当前体验，再安排文件管理、密码与登录验证。本轮核对现状并补充会话测试，不新增账户、密码或云存储实现，延续[02](02-architecture.md)、[22](22-course-submission-first-slice.md)与[21](21-github-deployment-and-handoff.md)。

## 当前结论

GitHub Pages已经发布最新的约4秒新生动效与作业展示流程。它是静态前端，本地星球和展示上传保存在每个浏览器的IndexedDB；推送GitHub不会上传学生作品。不同设备、浏览器及localhost/Pages之间不会自动同步。换设备目前需要主动导出、导入ZIP。

本机课程API已经有私人图片、不可变提交、教师评阅和会话鉴权，但只接受合成测试账户，启动入口仅绑定127.0.0.1且拒绝production。Pages的「课程作业」实际显示「在线课堂即将开放」，没有把测试账号公开成正式登录。

| 项目 | 当前实际状态 | 对正式使用的影响 |
| --- | --- | --- |
| 真实登录与密码 | 未实现；users保留auth_issuer/auth_subject，不保存学生密码；本机以测试账户选择进入 | 不能验收注册、首次激活、密码修改/找回或真实身份隔离 |
| 云端星球与展示图片 | 未接入；仍是IndexedDB/Blob与ZIP | 换电脑看不到原作品；老师没有共享班级宇宙与集中展示管理 |
| 课程后端公开部署 | 尚无正式身份源、HTTPS后端与私有对象存储 | 静态发布成功不等于在线交作业系统已开放 |
| 文件删除与空间回收 | 图层/草稿移除主要解除当前引用；历史素材与上传文件没有完整清理流程 | 删除画面内容不代表已释放磁盘或账户配额，不能直接清理历史原作 |
| 备份与恢复 | 本地ZIP已有校验和恢复；课程数据库与私有文件联合恢复未演练 | 正式班级上线前需确认数据库记录和实际图片能一起恢复 |

前三项是正式课堂上线的阻塞项，属于明确尚未建设的能力，不应把测试登录改个名称就对学生开放。文件清理与联合恢复也应在灰度使用前完成。

## 本轮已验证

47项相关模块检查通过：课程领域4项、课程Service 9项、HTTP/私人媒体10项、ZIP 10项、本地存储2项、自选展示12项；全套19文件140项检查及ESLint通过。新增3项HTTP检查验证旧cookie到期后失效、账户停用后旧会话/新登录均被拒绝、注入teacher角色与未知测试账户被拒绝。账户状态沿用既有active/inactive契约，不改SQL迁移。

已有检查覆盖匿名与伪造身份拒绝、Origin/CSRF、注销后失效、学生/同班老师/其他学生与其他班老师的媒体访问、老师看不到私人草稿、图片实际解码/hash、原始文件不可变、重交历史、幂等提交、数据库重开保留提交、ZIP原图一致/路径穿越/超限/损坏拒绝。以上测试使用合成素材与隔离数据库，不修改用户文件。

在线实际检查返回HTTP200，课程页显示未开放，无课程API请求、无测试账户入口、无浏览器运行时错误。部署的应用提交48198e5已通过GitHub核心与真实PostgreSQL检查，具体记录见[10](10-implementation-progress.md)。

这不等于已验收真实账号、密码管理、跨设备同步、云对象存储、容量耗尽或数据库与图片联合恢复；这些不能用本机测试身份代替。

## 代码检查发现的待复现问题

1. [CourseView.upload](../apps/web/src/features/course/CourseView.tsx)逐张上传，全部成功后才把附件加入当前草稿。如果第二张失败，第一张可能已经留在服务端，却不出现在当前草稿，也没有重新选择既有上传文件的入口。需要故障注入验证后决定保留逐张成功结果或提供暂存文件管理；这是潜在的文件丢失感和配额浪费，不代表服务器原图已丢失。
2. [PrivateMedia.upload](../apps/api/src/private-media.ts)先写original和display.webp，之后才进入数据库事务的清理catch。写展示文件失败可能留下没有数据库记录的原始文件；进程崩溃也可能产生孤立文件。当前数据库事务失败会清理两个文件，但没有覆盖所有写盘阶段，也没有孤立文件扫描。需要磁盘故障与重启测试后补齐清理、重试和可观测记录。
3. [草稿移除按钮](../apps/web/src/features/course/CourseView.tsx)没有服务端删除调用，配额按assets总原始字节计算。多次上传再取消/移除会继续占配额；清理必须判断草稿、不可变提交历史和展示档案的全部引用，不能以“当前列表看不到”为依据直接删原图。

以上是代码路径检查结论，尚未用故障注入复现；本轮没有把候选风险写成已修复或已完整验收。

## 下一轮建议验证顺序

先对现有本机课堂完成文件生命周期故障验证，再确定真实身份来源与云端部署方案。正式身份接入后，用同班学生A/B、教师、另一班教师和匿名访问者做完整测试，不使用同一个浏览器中的角色切换代替多人验证。

| 验证场景 | 通过条件 |
| --- | --- |
| 上传一张、取消、再次打开；批量上传第二张失败；重试 | 成功文件可找到且状态明确，失败不产生重复提交，有可追踪的暂存/清理结果 |
| 删除附件、替换图片、再次提交 | 当前草稿与不可变历史分开；仍被历史引用的原图能继续查看 |
| 换电脑或隐私窗口登录 | 同一账号可读取自己的云作品，不依赖原浏览器IndexedDB；他人作品不可写 |
| 首次进入与重复进入 | 首次可创建本人星球，再次进入只提供编辑，不因网络重试产生重复星球 |
| 登录过期、账户停用、退出、重新登录 | 服务器拒绝失效会话；本地未提交草稿保留并可在重新认证后恢复 |
| 密码/账户恢复 | 由正式身份系统处理，恢复不会授予教师权限，完成后相关会话按既定策略处理 |
| 学生A/B互猜图片或作业链接，其他班老师访问 | 服务器按真实归属与班级验证，拒绝越权；老师仍不能看私人草稿 |
| 模拟磁盘/存储写失败、数据库失败、断网重试 | 无ready记录指向缺失文件；原作/已提交版本保留；重试不重复交作业 |
| 数据库与图片一起备份、恢复到新环境 | 同一提交版本、hash、原图、展示图、教师反馈与权限关系全部一致 |

先做一个班级的受控灰度，再扩大班级范围。视觉与约30种成长元素继续按原计划迭代，不用美术验证替代身份与数据恢复验收。
