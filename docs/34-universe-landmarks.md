# 34 · 分散恒星与黑洞地标

日期：2026-10-11。按用户希望在大型宇宙中增加少量较大恒星、黑洞的反馈，扩展现有景观模块；沿用[31](31-classroom-space-and-boundaries.md)的空间与权限设计。

## 展示与空间

新增四颗恒星、两处黑洞，原近处黑洞保留，共七处地标。靠近初始视野的一颗暖金恒星便于发现；蓝白、红色和象牙色恒星散布于较远区域。不同尺寸的黑洞保留暗中心、暖色吸积盘、弯曲光弧和绕行尘粒。

| 地标 | 世界坐标 | 主体半径（世界单位） |
| --- | --- | --- |
| 暖金恒星 | (-2100, 400) | 400 |
| 蓝白巨星 | (11500, -6500) | 780 |
| 红色巨星 | (-12800, 7100) | 950 |
| 象牙色恒星 | (12800, 7600) | 620 |
| 原近处黑洞 | (1750, 820) | 103 |
| 西侧黑洞 | (-9600, -5200) | 515 |
| 东侧黑洞 | (6800, 3800) | 370.8 |

配置集中在renderer的`UNIVERSE_LANDMARKS`，使用固定世界锚点，与星球及单张星云使用同一个相机变换。学生星球绘制在景观之上；没有增加独立相机、缩放下限或重复贴图。地标自身不改变位置，恒星日冕缓慢呼吸，黑洞尘粒沿吸积盘绕行。全局暂停和减少动态效果同样生效。

景观不参与命中测试，在地标处仍可拖动地图。进入星球内部和编辑页面时隐藏；不创建Layer/AssetRecord，不改变学生作品、布局、归属、revision或ZIP协议。这些是环境装饰，尚未提供地标详情、命名交互或恒星物理模拟。

## 资源预算

- 四颗恒星共享一张挂载时生成的球面颗粒纹理，正常512×512 RGBA约1 MiB；低画质256×256约0.25 MiB。另有相同大小的Canvas像素源，不等于浏览器总内存；销毁renderer时释放纹理。
- 日冕、核心高光、黑洞光晕复用现有128×128辉光纹理。日珥与吸积盘Graphics只构建一次；没有新增图片请求、滤镜、shader、独立ticker或逐帧纹理上传。
- 黑洞尘粒沿用总量正常48/低画质16，分配到三处黑洞，分别16/16/16与6/5/5，不按黑洞数倍增。原游移星24/8与亮星24/10预算保持。
- 流星仍每90–120秒一颗、约1.65秒；背景64000×36000与部署40000×22500保持。低画质仍是renderer选项，没有手机自动降档或用户设置入口。

## 验证

新增两项模块检查：位置/光晕范围、主体间隔和远区分布；多个黑洞共享准确尘粒总量。完整模块、构建及发布结果见[实现进度](10-implementation-progress.md)。

新增七项隔离浏览器检查：初始恒星表面/光晕的实际像素；在恒星处拖动地图；围绕非中央鼠标点缩放实际表面；4%远景四颗亮恒星与三个暗中心/吸积盘；减少动态时像素冻结且文档不变；全局暂停/恢复；手机无横向溢出。六项背景同步回归继续比较世界投影后的真实云层像素。既有氛围脚本等待真实90–120秒间隔再检查流星、暂停和进出星球，不加速生产时钟。

测试使用独立浏览器存储，不导入用户数据库。软件WebGL可以验证视觉与交互，但目标机房GPU帧率、功耗和大尺寸恒星近景仍需实测。
