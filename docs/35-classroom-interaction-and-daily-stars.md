# 35 · 班级互动、每周探索与每日之星

日期：2026-10-11。状态：用户新需求与建议方案，尚未实施。沿用[02](02-architecture.md)、[03](03-data-model.md)、[32](32-artwork-first-and-growth-birth.md)与[33](33-upload-login-and-file-readiness.md)，不改变原作品协议或现有本地功能。

## 用户提出的课堂方式

- 星球和星球中的作品具有点赞、留言、表情互动；被关注、点赞或互动较多的星球与作品能在系统中明显展示，类似每日之星。
- 每周挑选1–2幅自己最满意的色彩作业上传展示，不要求把全部课程作业上传。
- 每位学生浏览所有同学的星球，至少发起5次与他人的互动。

这些是新增需求。下列统计口径、时间窗、去重和界面细节属于建议，尚未由用户逐条确认，也不是已经上线的功能。之前讨论过的真实登录、关注、点赞、留言与表情包目前均未实装。

## 首页与学生流程建议

宇宙首页设置简洁的「今日星光」区，提供星球与作品卡片：缩略图、作者、获选理由和进入按钮。点星球卡片定位并适度聚焦；点作品卡片直接欣赏原作，再提供去作者星球的入口。卡片可收起，在手机上避免遮挡地图和导航。

建议分开呈现三类发现入口：

| 入口 | 推荐依据 | 呈现与边界 |
| --- | --- | --- |
| 近期热门 | 当前班级近7天的有效互动，分别统计星球和作品 | 展示真实数量与统计窗口；不能标为艺术质量或成绩 |
| 今日之星 | 每日从符合条件的热门候选中轮换精选 | 同一作者建议7天内不重复占据精选席位；热门列表仍可正常出现 |
| 老师推荐 / 发现新作 | 教师显式推荐，或近期发布、较少收到反馈的作品 | 分别标注理由，不能伪装成人气第一或自动生成点赞 |

建议首页最多展示3张精选卡，星球与作品都有机会出现。数据不足时显示「本周新作」与探索邀请，不虚构每日冠军。星球旁可有轻量星光徽章，不能为了获选放大整颗星球、改变学生的配色或保存装饰；徽章属于展示界面，不写入PlanetDocument或ZIP。

学生登录后看到「本周探索」进度，例如：

> 展示作品 1 / 2（至少1幅） · 同学星球 18 / 29 · 有效互动 3 / 5

数字来自真实班级与活动规则，此例仅说明界面。可打开「还没看过」名单，提供「下一颗未探索星球」；已经浏览的有小标记。互动任务旁推荐尚未收到反馈的同学，点击后仍先欣赏作品，不强制自动点赞。

教师看到完成矩阵：每人上传数、浏览覆盖、有效互动和未完成项。任务完成情况仅学生本人和本班教师可见，不公开展示未完成名单；热门数量与任务进度分开。完成数量不自动换算艺术成绩，教师可以记录豁免或人工核对。

## 每周任务口径建议

采用班级时区（默认Asia/Shanghai）与明确开始/结束日期，服务器存UTC。每周一份规则版本，默认至少1幅、建议2幅；超出数量可留在个人作品集，不因多上传自动获得更多热度。作品以稳定ArchiveEntry计数，多张附件是一件作品，改名、编辑元素或重传同一来源版本不产生新的任务完成数。

上传和分享继续分开：只有学生显式发布到本班展示的作品才计入展示任务及发现入口，私人草稿不进入同学名单。班级可见不等于互联网公开；游客仅浏览另外发布的公开快照。

浏览所有同学的建议范围为该活动目标名单中、本班有效学生已分享的星球，排除本人。周初记录名单，尚无可分享星球的同学显示「等待创建/分享」，不作为他人的未完成项；教师可显式更新目标名单并显示变更，避免已完成进度悄悄失效。退班、停用或撤回分享的目标须由服务端移出并保留调整记录。

「看过」至少要进入内部且场景成功加载，仅外部选中、鼠标经过或地图缩放不计。建议累计前台可见停留约10秒，或打开一件原作并成功展示后登记；后台标签页、加载失败不累计。只保存必要的完成与粗略停留记录，不采集鼠标轨迹。这是浏览流程的完成证据，不能证明学生认真阅读，更不能直接用于自动评判学习态度。

用户原要求是「至少5次与他人的互动」。建议默认进一步分散到至少5位不同同学，每位同学本周最多贡献1个任务进度；这是待确认的教学建议，不能把它误写为用户已要求5位。规则预留「有效互动次数」与「不同同学数」两种模式，由教师在活动开始前选择。

点赞、预制表情、有效留言可构成互动；建议鼓励至少一部分具体留言，如「最喜欢的配色」「让我想到什么」「一个可尝试的变化」，但首版不擅自增加用户未要求的留言配额或硬性字数。关注主要用于订阅更新，建议不计入互动任务。本人点赞不计，教师操作和游客浏览不计入学生的同伴任务。反复取消/点赞、切换表情或重复提交不会刷出额外进度；删除或隐藏的内容按当前有效状态重新计算，保留调整记录。

## 热度与关注建议

热度独立于任务达标，优先使用近期不同同学的参与，避免把连续点击和上传数量当作受欢迎程度。首版建议：

- 星球热度汇总其自身及关联作品的互动；同一同学对同一作者每天只贡献一份最高权重的互动，不能点赞多个作品后重复推高星球。
- 作品热度按同一同学、同一作品、同一天去重；点赞或表情建议权重1，留言建议权重2，仅用于发现排序，不评价留言质量。界面说明算法与窗口。
- 关注星球是可取消的独立订阅关系，展示关注人数与更新提醒；「关注最多」可以作为单独列表。累计关注数不直接压过近期作品；已有关系不在每周自动变成一次新互动。
- 初期仅同班有效学生的互动贡献班级热度；作者本人、教师推荐操作、匿名访问和重复请求不贡献。公开游客或其他班级的互动后续另设范围。
- 每日精选由服务端按班级当地日期生成稳定快照，日内不随每次点赞跳动。候选建议至少收到2位不同同学的有效互动；同分轮换规则可重现，并保留策略版本。没有候选时显示新作。
- 撤回发布、教师隐藏或内容下架后立即从可见列表移除，即使当日精选快照仍记录其ID，也必须在读取时重新验证展示权限。

窗口、权重、候选门槛和轮换间隔均为首版提议，实施前以课堂反馈校准，不能声称已经验证其教育效果。首版不增加私信、付费投票、复杂总排行榜或模型自动评审。

## 架构与数据增量草案

继续使用模块化后端与PostgreSQL。统计由服务器执行，前端不接受自报总数或自选教师身份；班级与归属来自真实会话。互动不塞入场景JSON，不复用教师评分Reviews；目标绑定稳定的云端planet_id或archive_entry_id，不绑定可替换的造型preset或临时Layer。改元素、移动星球和恢复镜头不会断开原作品互动。

| 后续实体 | 主要用途与约束 |
| --- | --- |
| InteractionTargets | class_id、kind、planet_id、archive_entry_id；作品必须属于同一星球/班级；为可展示来源建立稳定目标，不接受任意本地UUID |
| PlanetFollows | actor_enrollment_id、planet_id、created_at；同班和发布权限校验，UNIQUE(actor,planet)，取消后不保留活跃关注 |
| Reactions | actor_enrollment_id、target_id、kind/code、created_at、updated_at；点赞与表情分别限一份当前状态，唯一约束防重复 |
| InteractionComments | target_id、actor、body、parent_id可空、visibility、deleted_at；纯文本/预制表情，教师仅本班管理；原作评论与教师评分隔离 |
| WeeklyExplorationActivities / Targets | class_id、开始/结束、timezone、rule_version、上传/浏览/互动模式及目标名单；规则变更留历史，不覆盖既有完成证据 |
| PlanetVisits | activity_id、viewer、target、first_opened_at、qualified_at、前台停留粗略值；唯一键防刷新重复，后台不增加停留 |
| ActivityEvidence / Adjustments | 指向已发布作品、合格访问和有效互动及豁免；服务端可重算个人进度，删除/退班调整可追溯 |
| DailySpotlights | class_id、local_date、slot、target_id、reason、policy_version、统计窗口与快照；UNIQUE(class,date,slot)，任务幂等并可重试 |

计划中的SocialInteractionService处理授权、幂等、取消与审核；ExplorationActivityService管理规则/名单/进度；SpotlightService聚合近7天互动并产生每日快照。简单定时任务即可，无需先引入微服务。必要索引围绕class/target/actor/time；先以一个班级负载验证，不在每帧或每次缩放重新计算排名。

接口按「读取可见目标与摘要 → 登录后提交/取消互动 → 获取本人周进度 → 教师读取本班进度/管理内容」分开。留言纯文本渲染、长度与速率有界；老师删除自己的/管理同班内容，学生只能删除自己留言；每次写入在事务内重新校验角色与发布状态。鉴权及跨班检查、会话过期、可见媒体白名单继续按[33](33-upload-login-and-file-readiness.md)推进。

## 分阶段实施与验收

1. 先完成真实身份、班级成员、私有云文件、星球/展示档案同步与明确班级分享。当前GitHub Pages只有本地作品，不能统计其他浏览器的学生行为。
2. 接星球/作品的点赞、表情、关注与取消；原作展示页保留显式编辑按钮，互动不直接进入元素编辑。随后加入留言及教师内容管理。
3. 实装每周目标、未浏览名单、去重进度和教师矩阵；优先让学生知道下一步去哪里，允许教师配置/豁免，不自动打分。
4. 有真实互动数据后加入近7天热门、每日精选、教师推荐和低反馈作品发现；以一个班级灰度校准分布，之后再做跨班公开展览。

每一步运行相关领域/数据库/HTTP与隔离浏览器测试并更新[10](10-implementation-progress.md)。至少覆盖重复/并发点赞与取消、换表情不刷数、作品造型变更后来源不变、留言删除/审核、跨班和私人草稿拒绝、截止与当地周界、后台不累计访问、目标名单调整、自己/游客/教师不增加同伴数、每日生成幂等、同作者精选轮换、撤回分享即时退出精选、移动端与减少动态。离线前端不显示假成功；登录后服务端重算并显示同步结果。

## 参考与判断边界

官方[Moodle Workshop](https://docs.moodle.org/405/en/Workshop_activity)将提交和同伴反馈分阶段，并支持教师手动或系统随机分配；[Canvas互评分配说明](https://community.instructure.com/en/kb/articles/660698-how-do-i-automatically-assign-peer-reviews-for-an-assignment)同样提供提交后的自动分配。它们用于参考「明确任务与目标、教师可管理」的流程，不证明点赞排行榜、10秒停留、5位同学或上述权重能提升学习成果。这些COLORVERSE交互提议需要课堂实测。检索日期2026-10-11。
