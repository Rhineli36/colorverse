# 参赛展示界面精修与实测记录

日期：2026-10-15。此记录更新 [49](49-unified-cloud-universe.md) 中的导航、任务引导、内部场景与图片策略；历史报告保留其生成时的状态。

## 实施内容

- 真实云端顶栏顺序为：**探索宇宙 → 我的星球 → 编辑星球 → 色彩的奥秘**。教师管理仍由真实班级角色控制。
- 暂停展示新手任务栏和“功能探索”入口。`apps/web/src/features/classroom/presentation-options.ts` 中 `showLearningGuide=false`；任务组件、完成规则、后端接口和已保存进度未删除。恢复该常量并构建即可重新展示。
- 大宇宙新增“显示姓名与学号”小开关，默认只显示星球名字，状态保存在浏览器。此开关只控制大宇宙的标签、聚焦简介和导航目录；内部作者署名仍保留，不改变数据库里的身份。
- 五个受管理的案例星球更名为：焰色失重、落日来信、森野绮梦、云隙漫游、月白棱镜；原来的默认风格名称没有冒用学生身份。
- 内部采用共享 `SceneLayout`：左侧寄语、创作碎碎念、课程感受；中央保存的背景与已有成长元素；右侧按作品列出真实提交时间。点击目录将焦点移至对应 `data-work-id` 元素并高亮，回车或点击元素打开原来的作品详情。
- `PlanetExplorer` 内部默认固定视野：不拦截滚轮，不提供缩放按钮，不拖动整张背景；正常上下滚动页面。大宇宙的缩放和平移继续保留。背景按原图 16:9 比例展示，元素相对坐标仍使用已有持久数据。
- 下方复用真实星球留言、点赞、表情接口，并展示已有互动时间。作者查看自己的留言板；沿用既有禁止给自己互动的权限，作者在自己的星球不显示发送表单。
- “色彩的奥秘”扩大为宽幅专题，分为“色彩知识”（K01—K07）与“色彩情感”（K08及12张已有情感色卡），继续复用同一内容数据。后续专题扩展尚未实施。
- 25件案例作品删除来源、演示账号、PPT提取方式等说明，保留原有创作内容并校订重复文字、标点和可确定的错字，例如“温柔合缓”“梦嗯对”“狐狸的成色”。原件和提取记录未修改。无原说明的作品保留为空，不补写学生原意。
- 侧栏新增文字属于按作品风格编写的演示手记，保存 `metadata.demoWriting=true` 并以小字标识，不能作为真实学生感言引用。老师原有预设分数仍标为演示建议，未改成真实课程成绩。学生自行保存介绍时不继续标记为预设手记。

## 外貌图片问题与处理依据

1. 五个实际云端 `planets/{id}/exterior` 接口逐一返回200、`image/webp`，分别约194446、94384、171686、61152、68776字节，证明图片未丢失。
2. 浏览器复现了原外貌请求 `net::ERR_ABORTED`；原组件给私有图片设置的10秒中止时间会让慢请求进入默认图回退。此前只观察作品图片200不足以证明外貌首屏正常，本次单独检查外貌。
3. 五个已获准发布、原本就在展示包里的案例外貌使用 `competition/cloud-exterior-previews.json` 的**星球ID + 当前mediaId**匹配本地公开预览。只读取该五个已授权图片；新上传外貌的mediaId不同即失配，回到私有接口。普通学生图片继续走认证接口，没有把私有桶改公开。
4. 在加载映射前不启动图片预取或渲染，避免先发起旧的私有请求再误报失败；其他私有外貌等待时间由10秒延长至25秒。失败提示和手动重试仍保留。
5. 实际浏览器收到五个版本匹配的案例外貌预览200；视觉截图可确认五种图案，不是普通默认球体。不能据此宣称所有地区、所有未来图片都没有网络问题。

## 后端保存和数据范围

- 新增 `reflection`、`courseNotes`、`demoWriting` 进入现有星球文档metadata与appearance接口，继续使用原有作者所有权及revision并发校验，不另建模拟数据库。
- 新增 `PUT works/{id}/description` 以作者身份校订已有案例说明；限制当前班级、作品所有者、未撤下状态、revision与2000字长度，不允许同学或教师代替作者覆盖。接口不是免登录批量管理入口。
- `scripts/sync-exhibition-classroom.mjs` 仅处理已有五个受管理案例、10张已授权图与25个已有元素；不创建或覆盖真实课堂学生。
- `scripts/sync-exhibition-details.mjs` 仅清理这25件已知作品，使用五个演示账号调用真实权限接口。本轮增加14条实际互动记录，内容标明“演示留言”，请求ID确定，重复执行不重复造数。浏览器验收另留一条明确标记的演示留言。
- `scripts/refresh-competition-snapshot.mjs` 改为通过真实登录和只读API提取五个已知案例，避免依赖当前不通的本机PostgreSQL代理。快照只导出已知演示账号互动；不导出全班名册、原始存储键、令牌或数据库密码。
- 静态展示含上述手记、目录与已有留言快照；静态入口仍明确只读，发送留言链接指向真实云端，不声称静态点赞/留言会写数据库。

## 验证范围与证据

- ESLint、TypeScript与云端/静态两类生产构建通过。既有第三方PURE注释警告仍存在，未导致构建失败。
- Vitest：29文件、219测试通过；新增真实SQL检查作者保存、同学/教师拒绝、跨班拒绝、旧revision拒绝及超长输入拒绝。
- 浏览器实测见 `outputs/presentation-refinement-acceptance.json`，脚本 `tests/presentation_refinement_browser.py`；包含真实云端与本机静态页面，未mock上传、身份或互动API。
- 图片、目录、滚动、作品详情、教师点评与同学留言入口、手机尺寸点击、专题切换、留言刷新和重新登录保存、新增侧栏字段隔离班级写入及读取等，以该JSON中的实际通过条目为准。
- 本轮没有重新执行真实教师打分写入和新作业上传；这些接口/成长规则保留，前轮证据仍在 `outputs/exploration-upload-acceptance.json` 与此前评分验收记录。本轮不将打开评分区域等同于新增评分端到端验收。
- 构建后的静态ZIP继续用阻断外网的浏览器验证，结果见 `outputs/competition-package-acceptance.json`。

测试环境为Windows Chrome、软件WebGL和本机HTTP代理。手机部分是390px触控模拟；不是实体手机验收，也不能证明比赛现场或中国大陆无代理可达。服务端重启后的完整生产恢复、本轮全新电脑后端部署、后续色彩情感专题扩展均未重新验证。
