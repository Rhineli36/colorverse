# Excel 点名册与学生账号

## 使用方式

教师登录后进入“教师管理”，在“发布作业”旁点击“导入学生”。选择自己管理的班级，上传 Excel，核对预览，再确认生成，完成后下载账号清单。

模板只含“学号、姓名”两列，界面可下载。首版支持 `.xlsx`，每次最多 500 人、文件不超过 4 MB。点名册上方可有课程标题和合并单元格；导入器在前 50 行中寻找同一行的学号和姓名表头，底部签名不作为学生处理。班级始终由界面选择，不读取 Excel 中的其他班级字段。

学号按文本保留前导零；数字单元格使用简单的补零格式时也保留显示位数。已被 Excel 丢弃、没有文本或补零格式记录的前导零无法推断。超过数字精度的学号和公式输入会提示改成文本后核对。

预览标出空值、重复学号、姓名冲突等问题。存在问题时不能确认；先修改 Excel 后重新上传。预览不会创建账号。本轮提供的原始点名册已验证可读取，仅进行预览，没有替负责人批量开通真实学生。

## 学生登录与激活

- 登录框统一显示“账号、密码”，仍支持已有课堂邮箱。
- 新导入学生可用学号登录；清单另含完整登录账号，用于不同隔离环境出现相同学号时区分身份。
- 首次选择“首次激活学生账号”，填写老师提供的账号和激活码，设置并确认自己的密码，再登录进入所属班级。
- 激活码只使用一次。已激活账号不能再次使用旧码修改密码。
- 已有学生按原内部身份关联班级，保留原密码、星球和作业，不重新发放激活码。原来使用邮箱的学生也继续可用邮箱登录。
- 学号对应多个现有学生，或姓名不一致时停止该条处理，交由维护者核对，不自动合并身份。

正式课堂中跨课程的同一学生复用已有账号。独立评审课程登记在 `isolated_account_courses` 中，导入时只匹配自己的评审身份，不会因学号相同而关联真实课堂学生。该隔离登记仅维护者可修改。

## 结果和中断恢复

账号清单包含学号、登录账号、姓名、班级、首次激活码、创建结果和说明。结果为“新建、已有、失败”。失败条目不会显示为成功，可以修正问题后重新导入；已有账号密码保持不变。

后台逐条创建真实 Supabase Auth 账号和班级报名关系。导入批次有稳定编号，进度与结果保存在后端；同一教师刷新后可以恢复上次导入并重新下载。重新处理同一批次不会重复创建已完成的学生。激活码结果加密保存，只允许该批次发起教师读取；普通学生、游客、其他班级教师无权导入或读取清单。密码由现有认证服务管理，前端和业务数据库不保存学生设置的明文密码。

离线展示版保留同位置入口，点击后只显示：

> 课堂版支持导入 Excel 点名册，批量开通学生账号。本离线体验版使用预置身份，账号导入请在云端版操作。

“知道了”关闭，不请求云端，不生成虚假账号。本功能不改变 EXE 封装方式。

## 维护与部署

数据库新增迁移 009、010，通过 `node scripts/classroom-setup.mjs --proxy` 应用；服务端继续沿用已有 Supabase 管理密钥和受限数据库连接，密钥不进入前端。评审专用课程由维护者登记隔离；`scripts/judges-demo.mjs --provision` 在建立评审课程时自动登记。

评审恢复仍限维护者执行。除原有四个体验身份外，允许核验属于该专用评审课程的导入学生；恢复时归档他们的原评审班，保留其历史账号和作品，不把追加学生自动加入重建的初始示例班。出现其他身份或课程来源不明确的成员时拒绝恢复。课堂数据不受影响。

两个简化评审账号及密码放在 `work/参赛体验说明_私密.md`，不写入公开页面、源码或展示包。
