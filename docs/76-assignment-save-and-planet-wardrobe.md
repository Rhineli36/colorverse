# 课堂作业先保存后发布与装扮星球入口

日期：2026-11-04。分支：`codex/classroom-assignment-save-wardrobe`。

## 本轮范围

仅更新线上课堂及独立装扮预览。比赛 `/review/`、`/exhibition/`、比赛 Worker 与已交付 EXE 保持冻结。

- 教师新增作业按钮为“保存作业”，先持久化教学内容与可选示范图，状态为未发布。保存返回作业选择栏并选中新作业；未发布项目标注 `[未发布]`。
- 点击“选择发布对象”，确认全班或指定学生、截止时间后才生成发布记录和应交名单，并通知对应学生。取消确认不发布，保存后刷新仍可选择。重复保存沿用原请求 ID，不生成重复作业。
- 学生不能从教学任务列表读取未发布的自定义作业；未发布示范图继续沿用教师专用权限。学生不能调用教师新增作业接口。
- 学生主导航新增“装扮星球”，读取本人星球外观、内部背景及已有图片构图，复用可编辑 SVG 边框、星环与拖动浮饰。无星球、加载失败有独立提示；保留全局音乐组件。
- 七款边框底部列出确认的条件：双图片上传、互动达到20、累计获赞达到10、课程作业达到5/10、互动达到50、指定立冬作业提交并获教师评分。立冬作业暂未绑定，不按标题猜测。星环条件仍待配置。
- **本轮只提供试戴，未实现自动计数、资格发放与装扮套用保存。** 卡片保持锁定并明确说明，试戴返回不更改实际星球。没有伪造进度，也没有浏览器自行发放资格。后续接服务端资格与保存时沿用同一套图形组件。

## 实现与兼容

课堂专用 Worker 的自定义作业创建写入已有 `learning_task_settings.published=false`；原冻结 Worker 不重新发布，旧模式创建行为保留。正式发布继续使用原有 `classroom_publications` 和 `classroom_recipients` 快照接口、权限与幂等逻辑。教师三标签中的发布入口使用同一流程。

不需要数据库迁移；不批量修改既有作业或发布状态，不清库、不重建。已有学生、星球、提交、评分和通知保留。

独立预览组件抽为 `GrowthPreview.tsx`，原 `main.tsx` 只负责独立页面挂载。样式全局规则限制在 `.gp-app`，不覆盖课堂正文或按钮；星球图片固定方形圆蒙版，防止通用图片容器拉伸。

## 验证

- TypeScript、ESLint、全套 Vitest：45个文件、292项通过。
- 增加真实 PostgreSQL 兼容测试：保存后教师可读、学生不可读、无发布/无通知、重复保存不重复、学生写入拒绝、确认发布生成应交快照与学生通知。
- `tests/classroom-save-wardrobe-browser.py`：生产前端＋隔离接口验证保存、自动选中、取消发布、刷新再发布；学生本人星球、条件文字、立冬及星环试戴、窄屏、返回不保存。截图在忽略目录 `outputs/classroom-save-wardrobe/`。
- 上线验收使用独立虚拟验收班和账号，不给真实班级发送测试作业。实际发布版本及真实接口验收结果在发布完成后补记。

## 发布与后续

使用 `pnpm classroom:next build` / `pnpm classroom:next deploy` 更新 `colorverse-classroom-next`，正式入口仍为 https://colorverse.de5.net/ 。独立预览使用 `pnpm growth:preview deploy`，不修改域名网关或课堂绑定。

周末立冬作业可先保存，再从下拉菜单选择并确认发布；发布记录 ID 可供后续指定皮肤解锁绑定。当前不会因标题含“立冬”自动发放皮肤。
